## 1. Assumption under test, and what follows if it is false
Strictly, the pilot tests **nothing**: it is descriptive calibration, excluded from every tally ([X4-integrity §3](X4-integrity.md)). Its working premise [G]: on the quiet-machine profile the per-run and per-block noise of a `hearth-c-ref` A/A comparison is small and stationary enough that the e-process horizons `N` and clips `c` derived from it are affordable within ROADMAP §10's quiet hours. **If it is false** (σ_d large, heavy outliers, non-stationary nights), the derived `N` and quiet-hour totals rise. That feeds **owner question 1** of the X4 record and the **D-22** second-box trigger (ROADMAP §9). The pilot never kills and never passes a gate.

## 4. Units and counting rules (defined before data)
- **Run type**: a §3 column. Every estimator is per run type; nothing is pooled across run types.
- **T, the timed quantity (revision 4; review R2-8):** every per-run time below (ln(ns), d, σ̂_run, the incumbent median, t_run) is **Δ_h = t1 − t0** in ns of a run accepted under the bracket, the harness interval of MEASUREMENT §3 step 8. Δ_o is recorded beside it and enters only the bracket (|Δ_h − Δ_o| ≤ τ_clock). The block record names its clock (`ln_delta_h_ns` in `blocks.jsonl`).
- **σ̂_d** (per run type): the root mean square of the A/A block statistic `d = ln(T_B/T_A)` **about the null mean 0**, over all non-discarded blocks of all non-voided sessions of that run type; `B` = that block count; `df = B` (the mean is known, not estimated: identical binaries, randomised order). Function: `stats::rms_about_zero`. Between-session variation stays in σ̂_d because the e-process sees it. This is the X4-integrity §7 / MEASUREMENT §5.4 quantity ("pooled SD of the pilot's A/A block d") made precise, not the within-session SD.
- **σ̂_U** = σ̂_d · √(B / χ²₀.₁₀,B): the one-sided 90% upper bound, `stats::sigma_upper_90(σ̂_d, B)`.
- **σ̂_run**: the pooled within-(session, arm) SD of per-run ln(ns), `df = Σ(n_g − 1)`, `stats::pooled_sd`.
- **Pilot incumbent median**: the grand median of per-run ln(ns), by run type.
- **t_run**: per-run Δ_h (ns; revision 4, was Δ_o); its median and 1st/99th percentiles by run type. All quantiles in this record are **nearest-rank**: the ⌈p·n⌉-th smallest value, `stats::quantile_nearest_rank`.
- **Per-run slow-outlier rate and p0** (two passes): pass 1 computes σ̂_run and the pilot incumbent median from all non-discarded runs; pass 2 replays the R scorer per session in run order with `c_run = 4·σ̂_run` and the pass-1 median as the reference before an arm has history, and counts slow flags. p0 = the one-sided 95% Clopper–Pearson upper bound of that rate (`stats::clopper_pearson_upper`).
- **Void and discard rates**: discarded blocks ÷ attempted blocks; voided sessions ÷ attempted sessions, by tier (§10).
- **Counted set**: every non-discarded block of every non-voided session. The pilot has no gate, so there is no "first 100" rule. **Revision 5 (review round 5, finding 7), made exact:** a session is counted only if progress.txt ends it `completed`. The partial blocks of a session that ended `integrity_stop` (an evaluator failure, §10), `error` (a set-up error of the driver) or `interrupted` (a started line with no end line: a crash, a restart, a power loss) are excluded like those of a hygiene void or a `cut` session, and the estimator reports each count by end. A block that holds a capped run is left out of σ̂_d and σ̂_run (σ_d comes only from runs that reached their stopping point, §8) and enters the slow-outlier replay as slow. Function: `estimate::estimate` (`x4svc pilot-estimate`, §7).
- **Descriptive only**: the within-session SD of d (`stats::pooled_sd` over sessions) and s_between, the SD of session means of d.

## 9. Threats to validity and how each is handled
- **Non-stationary nights fake low or high σ_d.** Randomised ABBA/BAAB; S3/S4 reported; between-session variation is kept in σ̂_d because the e-process sees it (§4).
- **Carry-over within a night.** The §4.1 per-run start-state gate and the carry-over contrast; a gate timeout discards the block (§10).
- **Interactive use, GEMS or a stray job in the window.** The §10 sensors void the session: an excluded image starting or using CPU, a **started-only** image starting (a remote login, an agent's or a scheduled task's shell), another Mithril binary by image name, input, a new session; GEMS is a co-tenant Pierce keeps out (D0-10d), and agents stay off the desktop in the window (D0-7a, PRE-NIGHT B). **Revision 5 (review round 5, finding 4):** the record no longer relies on the desktop job wrapper of OWNER-QUEUE B13 (DELEGATED P19 adopted its design only; no wrapper exists in the repository [M, grep, 2026-10-23]); a Mithril job that starts in a window is caught by these voids, not prevented. If the wrapper is built later it adds prevention; it must then exempt the pilot launcher. Whether GEMS counts as "the Owner's own use" for D-22 is open (A18 / D0_BRIEF Q7).
- **Censored tolerances.** Observe mode up to stated ceilings (§3).
- **Selection through voids.** Discard and void decisions are computed by a sensor-only function that never receives run times or d (§10). Revision 4 (review R1-5) removes two ways run times leaked in: the background-CPU discard is judged over the **planned** block time (a fixed cycle budget per run type: 1% of one core × 4 × (t_run,plan × c + o_rt)), not the observed block time, which contains the four run times; and the 07:00 cut, which falls on a real clock advanced by the session's own run times, is made rare by the planned end with o_rt and t_run,plan(e2e) measured as an overestimate (§6). Cut sessions are recorded with the end `cut` and their completed blocks, and the post-pilot amendment **reports σ̂_d both with and without the cut sessions' blocks, with the cut count** (the estimator itself uses the void rule: without).
- **Host noise read as an integrity failure** (revision 4; review R1-11). A launch delayed by the host past the 2-s pre-START wall ceiling (a reviewer's daytime dry night: 3.64 s wall at 0.78 × 10⁹ cycles, with the run LP's SMT sibling at 100% [M]) fails the run and **stops the pilot** as an evaluator bug, under the stricter reading this record registers (§3); a Pierce-cleared integrity stop is needed before the next night. The run core rule of §10 (the run LP and its sibling quiet before every run) and the pinned binaries' local cache make it rarer [inference]; the pre-night amendment records the pre-START wall distribution of the 3 dev runs that fix K. Whether the wall bound is judged or only recorded in the pilot is open before freeze (§3); judging cycles only is the reviewer's recommendation.
- **Blind spots that remain** (revision 4). A listed process that lives less than one 250-ms poll between two checks can be missed; GPU use between two checks (nvidia-smi samples at each check, about every 3–15 s in a microbenchmark block) can be missed; a spurious condition-variable wake-up can consume another thread's pending wake (§2). Each is recorded as a limit, not a rule.
- **Profile not applied.** `x4svc verify-profile --collection --pins` refuses the night on any mismatch, and (revision 4) is repeated at every session start, a mismatch voiding the session; core parking is re-read after every block and the plan GUID at every check; the service never changes a setting.
- **Circularity.** The pilot's constants are used by the *later* calibration only.
